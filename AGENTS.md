# AGENTS.md — DentalCare Frontend

Admin dashboard for a dental clinic (patients, doctors, appointments, medical records, calendar, dashboard).
Talks to the Spring Boot API in the sibling repo `dentalcare-backend`.

## Stack

- React 19.2 + TypeScript 5.8
- TanStack Start (SSR) + TanStack Router (file-based routing) + TanStack Query 5
- Vite 7, Tailwind CSS 4, shadcn/ui (Radix primitives), Lucide icons
- Axios (HTTP), react-hook-form + zod (forms/validation), Sonner (toasts)
- ESLint 9 + Prettier

## Commands

```bash
pnpm install        # install deps (pnpm is the canonical package manager)
pnpm dev            # dev server on port 5173
pnpm build          # production build
pnpm preview        # preview production build
pnpm lint           # ESLint
pnpm format         # Prettier --write
```

Environment: create `.env` from `.env-template` with `VITE_API_URL=http://localhost:8080`.
`.env` is gitignored — never commit it.

## Project structure

```
src/
├── api/           # One Axios instance per entity + auth interceptors
│   ├── interceptors.ts        # setupAuthInterceptor(): Bearer header + 401 → /login
│   ├── auth.api.ts, dentalcare.api.ts (patients), doctor.api.ts,
│   ├── appointment.api.ts, medical-record.api.ts
├── actions/       # Plain async functions that call the api/ layer
├── hooks/         # TanStack Query hooks: usePaginated*, useCreate*, useUpdate*, useDelete*
├── contexts/      # auth.tsx — session/auth context
├── routes/        # File-based route pages (TanStack Router)
│   └── __root.tsx # Layout shell + auth guard
├── components/
│   ├── ui/        # shadcn/ui primitives — do not hand-edit beyond regenerating
│   └── *.tsx      # Feature components (AppSidebar, AppointmentDialog, DataPagination…)
├── types/         # Interfaces & enums shared with the API contract
├── lib/           # utils.ts (cn helper), mockData.ts, error handling
└── routeTree.gen.ts  # GENERATED by TanStack Router — never edit by hand
```

## Conventions

- **Data flow**: `api/` (Axios instance) → `actions/` (async fn) → `hooks/` (useQuery/useMutation) → `routes/` (component). Do not call Axios directly from components.
- **Query keys** follow `["entity", scope]`, e.g. `["patients", "all"]`, `["patients", { page, size, sort }]`. Reuse these exact keys when invalidating cache — inventing a new key shape silently breaks invalidation.
- **New entity checklist**: `types/*.interface.ts` → `api/<entity>.api.ts` (call `setupAuthInterceptor`) → `actions/<entity>/` → `hooks/usePaginated*`, `useCreate*`, `useUpdate*`, `useDelete*` → `routes/<entity>.tsx`.
- **Auth**: JWT access + refresh tokens live in `localStorage`; the interceptor injects `Authorization: Bearer …` and a `401` response clears tokens and redirects to `/login`.
- **Forms**: react-hook-form + zod schemas; uniqueness of email/phone is validated pessimistically against the in-memory list.
- **Styling**: Tailwind CSS 4 + shadcn/ui tokens only. No inline styles, no CSS modules, no new UI libraries without asking.
- **Client-side search/pagination is intentional**: pages fetch once (up to 10k records) and filter in memory. Keep that behavior when touching list pages unless the task explicitly changes it.

## Known quirks (read before editing)

- `vite.config.ts` is intentionally thin: `@lovable.dev/vite-tanstack-config` already registers the TanStack/React/Tailwind/Cloudflare plugins. **Do not add those plugins manually** — duplicates break the app (see the comment in `vite.config.ts`).
- Two lockfiles exist (`pnpm-lock.yaml` and `bun.lock`). pnpm is canonical per the README; if you install with another manager, the lockfile drifts.
- `package.json` `name` is still the template default `tanstack_start_ts` — rename with care (it is cosmetic but visible).
- `src/lib/mockData.ts` and `src/lib/appointmentsStore.ts` are leftovers from an earlier mock-driven version; prefer real API data in new code.
- Deployment target is Cloudflare (`wrangler.jsonc`, `@cloudflare/vite-plugin`); `pnpm build` output must stay compatible with the Workers runtime.

## Testing

- **No test framework is installed** (no vitest/jest, no test files, no CI workflow).
- When adding tests, use Vitest + React Testing Library, co-located as `*.test.tsx`.
- Minimum useful coverage for new work: one hook test (query/mutation behavior) and one route/component test per new page.

## Backend contract

The API surface and auth flow are documented in `README.md` (Tech Stack, Features, API Endpoints tables).
Route prefixes are inconsistent on the backend (`/api/auth`, `/api/users` vs `/patients`, `/doctors`, `/appointments`, `/medical-records`) — mirror the exact paths in `src/api/` and never "normalize" them on one side only.
